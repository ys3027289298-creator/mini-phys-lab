结论先行

①没发现，不是因为覆盖率不足——覆盖率已经满了。事故前三个模块行覆盖 100%、调用执行 100%，28 个断言却没有一个提及物体类型；仓库里根本不存在 kinematic / dynamic / kind 这个词。

②反解证明覆盖不是这道题的护栏。把「已声明类型的调用点 k」设为 0，要兜住哪怕一次标错，反解得需要 100% 覆盖；而 100% 已经达成、事故照样发生。能把这个所需覆盖压到 0 的唯一办法，是让每个调用点都必须声明类型——也就是把类型变成编译期强制。

01为什么当时没发现

先把「类型标错」的调用点统计出来，再用这个占比反解需要的覆盖率。统计之后结论比预想的更硬：这里的问题不是「标错」，而是根本没有地方可以标。

02反解：需要多大比例的测试覆盖

设 11 个运动调用点里已有 k 个声明了类型。要让「至少 1 个标错调用点被测试拦下」成为必然，须覆盖全部 11−k 个未标注点，即所需覆盖率 f = 1 − k/N；若要 80% 把握，则 f = 1 − 0.2^(1/(N−k))。

把现实的 k=0 代进去，得到 100%——而 100% 正是事故前的实测值。也就是说，「加测试、提覆盖」这条路径反解出的目标已经达成，事故仍然发生。这页数据本身否证了覆盖率是护栏：缺陷不在某条没跑到的分支里，而在接口里没有这个概念。

模型说明：1−k/N 假定各已标注点被独立抽样。它只在「各点已声明类型」的前提下成立——而事故前 k=0，前提本身不成立，所以 100% 也兜不住。这个模型的自我否证，恰好是结论：唯一能把所需覆盖降到 0 的，是必填。

03设计约束：把类型做成接口的必填参数

目标不是「记得传类型」，而是不传就编译不过；进一步，传字面量 0/1 也不行，只能用具名常量。缺了编译不过，错误就在编译期暴露。

三个要点

  • 必填、无默认。step(BodyType t, Body* b, …)。参数在第一位，调用点无法省略。
  • 结构体包装，而非裸 enum。typedef struct { BodyKind kind; } BodyType;。标量字面量 0/1 不能隐式转换成结构体——裸枚举在 gcc 与 clang 最大告警下都会静默接受字面量（见取舍一节实测）。
  • 策略 switch 穷举 + -Wswitch-enum。以后新增 body kind 而不给策略，编译直接报错，逼你当场决定运动学怎么处理。

核心实现（integrate/src/integrate.c）：

static int is_simulated(BodyType t) {
    switch (t.kind) {
    case BK_DYNAMIC:   return 1;   /* treat as a real body */
    case BK_KINEMATIC: return 0;   /* path is authoritative */
    }
    return 0;   /* unreachable; keeps -Wreturn-type quiet */
}

int step(BodyType t, Body* b, float dt, …) {
    if (dt < 0.0f || radius <= 0.0f) return -1;
    if (!is_simulated(t)) return 0;    /* kinematic: don't touch */
    …

这次事故的根因——位置修正会「推」一个本该沿既定路径走的物体——被一行 if (!is_simulated(t)) return 0; 关掉；resolve 同理，运动学物体质量无穷大，速度不被改写。

04取舍：改动行数 vs 复发风险，定方案

三个候选实测对齐（同一改造范围、两模块、只算签名+策略+调用点，不计新增回归断言）：

两张图用同一组横轴分类、各自独立纵轴——刻意不做双纵轴，因为改动量与复发风险量纲不同，叠在一张图上会凭空造出相关性。

为什么默认值方案被否掉：它实测复现了这次事故。

把 kind 做进 Body 字段、零初始化默认成动态：7 行改动、0 调用点迁移、仍然 all_ok=1。但把一具本该运动学的物体交给它，编译器在 -Werror（含 clang -Weverything）下零告警，物体被从 y=0.25 推到 0.500、vy 清零——与事故一模一样。「方便」的代价就是「会再犯」，实测坐实。

定方案

选「结构体必填」。两条曲线在「默认值→其余」之间有一道断崖：多花 29 行，把静默形态从「处处可犯」压到 0；而在裸枚举→结构体的最后 6 行，买到的是「字面量 0/1 也无法伪造」——这笔边际账很划算。默认值省下的 29 行，等于把这次事故原样存进代码库里，等下一次场景拼装时再触发。

若团队时间被极端挤压，裸枚举必填可作为中间态：它已能拦下最常见的「漏标」，但字面量仍可伪造。底线只有一条——不能有默认值。

05两类调用点各改一处样例

两类边界：冲量响应（solve/resolve）与运动积分（integrate/step）。各取一处，展示改动前后。

样例 A — 冲量响应类（solve）

/* 前 */
resolve(&v, n, &m, &loss);

/* 后：动态物体，允许被冲量改写 */
resolve(BODY_DYNAMIC, &v, n, &m, &loss);

/* 后：运动学物体，速度必须原样返回 */
resolve(BODY_KINEMATIC, &kine, n, &m, &kine_loss);

样例 B — 运动积分类（integrate）

/* 前 */
step(&b, 0.1f, 0, -9.8f, 0.0f, 0.5f);

/* 后：动态物体照常积分并做地面修正 */
step(BODY_DYNAMIC, &b, 0.1f, 0, -9.8f, 0.0f, 0.5f);

/* 后：运动学物体——不积分重力、不做位置修正 */
step(BODY_KINEMATIC, &k, 0.1f, 0, -9.8f, 0.0f, 0.5f);

这两个调用点连同其余 9 处全部迁移。之所以能一次性、机械地迁完，是因为编写者不必逐个回忆哪具物体是什么——编译器会把每一处缺参的地方列出来（见下节）。

06验证：编译必须失败得恰到好处

「恰到好处」有两半：漏标的要报错，标对的零告警。仓库内新增 make -C solve contract，对 8 个形态逐一单独编译，判定只看「编译器是否报错」。若某个应被拒绝的形态竟然编译通过，该测试自己就失败。

漏标的典型报错（GCC）：

error: incompatible type for argument 1 of 'step'
error: too few arguments to function 'step'

编译契约测试自证：8 / 8 通过（cc 与 clang 各一遍）。三个模块在 -Wall -Wextra -Werror -Wswitch-enum -pedantic 下全部 all_ok=1。

新增的行为回归

  • integrate：kinematic_not_corrected、kinematic_path_unchanged——运动学物体被压进地面时坐标逐位不变。
  • solve：kinematic_untouched、kinematic_velocity_unchanged、kinematic_no_impulse_loss——速度逐位不变、冲量损失为 0。

题面要求「各改一处样例」；实际把所有 11 处都迁了，是因为编译器逐处点名、迁完才可能全绿——这正是必填方案把迁移成本变成一次性机械劳动的地方。

07仍然存在的盲区（说清楚，不粉饰）

  • 编译器拦「没标」，拦不住「标反」。有人显式写 BODY_DYNAMIC 而心里想的是运动学，照样编译通过。这类语义错标只能靠行为断言（上面 5 条回归）兜底，且只在覆盖到该调用点时有效。设计约束缩小了错误面，没有消灭它。
  • 类型块在 solve.h / integrate.h 各有一份（用同一个 BODY_TYPE_H 守卫保证同 TU 不冲突）。两份必须字面一致，是维护隐患；长期正解是抽一个共享 phys_types.h，但那会把两个独立可构建的模块耦合起来——留作后续决策。
  • 「运动学物体质量无穷大」是建模选择，不是物理真理。若某场景需要一个「会动但不受冲量影响」的混合体，需要新增 kind，届时 switch 穷举会强制你决定策略。
