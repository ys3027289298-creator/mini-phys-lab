# penetration

Turns “球不能穿过地面” into a numerical acceptance spec and checks it at three
camera distances. `make test` runs the spec.

## 1. 穿透深度的定义式

球心到地的距离许可有一个明确写法，模块里只有这一个（`src/pen_depth.h`）：

```
h = plane_y + r - y_c
```

| h | 含义 |
|---|---|
| `h > 0` | 球心低于表面 `h` 米，即穿透深度（**本文的“穿透深度”只指这个量**） |
| `h = 0` | 恰好接触 |
| `h < 0` | 离地 `-h` 米 |

“允许残留多少”= 允许 `h` 在修正后仍留下的值，记作 `allow`。规格的关键不是
`allow` 取多少毫米，而是它对应的**屏幕误差**是多少。

## 2. 残留穿透 → 位置修正

`integrate` 的每帧顺序是「积分 → 修正 → 呈现」，所以观众看到的是修正后的深度。
设修正系数为 `β`（修掉测得深度的百分比），一帧里：

```
h'  = h - β·h      = (1-β)·h          修正后残留
```

但球在接触时速度被清零，重力每帧又把自由落体增量 `d = g·dt²` 加回深度：

```
h_{n+1} = (1-β)·h_n + d
```

稳定在 `h* = d/β`，故**每帧残留**为

```
residual = (1-β)/β · d
```

| β | 残留 | 结论 |
|---|---|---|
| 1 | 0 | 修正帧不留残留 |
| 1/2 | `d` | 比 β=1 多留一帧的自由落体量 |
| 1/4 | `3d` | 继续变差，β→0 时发散 |

所以数值规格必须取 **β = 1**（一帧修到表面），唯一可调量变成**死区配额 `allow`**。
`src/penetration.c` 第 4 节会用仿真校验这条闭式。

## 3. 用可接受的视觉误差反解配额上限

一毫米近处看得见、远处看不见，所以上限按**屏幕占比**给。投影：

```
f      = sensor_px / (2·tan(vfov/2))        = 935.31 px   (1080p, 60° VFOV)
px     = h · f / R                          R = hypot(D, camera_h)
A_vis  = 1.0 px 对应的深度 = 1.0 · R / f     (可见阈值)
A_cap  = 0.5 px 对应的深度 = 0.5 · R / f     (可接受视觉误差)
allow  = min(A_cap, 25%·r)                  (25%·r 只是防呆)
```

各档取到的配额（**这就是需求里要报的数**）：

| 档位 D | 斜距 R | A_vis (1 px) | **allow (0.5 px)** | 占半径 |
|---|---|---|---|---|
| 3 m | 3.354 m | 3.586 mm | **1.793 mm** | 0.36 % |
| 10 m | 10.112 m | 10.811 mm | **5.406 mm** | 1.08 % |
| 30 m | 30.038 m | 32.115 mm | **16.058 mm** | 3.21 % |

注意数值随距离线性放宽：3 m 档几乎是 10 m 档的 1/3、30 m 档的 1/9。固定毫米
上限在 30 m 会过严（每帧都修），在 3 m 会过松（肉眼可见），这正是需求要求
按屏幕占比而非常数的原因。

## 4. 取舍：两条曲线定上限

配额宽 → 少修正、但可能被看见；配额严 → 每帧都修、成本高。两条曲线
（`make curves` 生成 `../docs/penetration-curves.csv`，图见
`../docs/penetration-curves.html`）：

- `visible(allow)`：60 s 内被看见陷进去的连续事件数；`allow < A_vis` 时为 0，
  跨过 1 px 后跳升。
- `cost(allow)`：修正帧占比。深度每帧长 `d`，每隔 `m = ceil(allow/d)` 帧修一次，
  成本 = `1/m = d/allow`，随配额下降。

实测可见性跳变点（第 1 个非零配额）：

| 档位 | 首次可见（px） | 事件数 |
|---|---|---|
| 3 m | 1.10 | 1 |
| 10 m | 1.05 | 583 |
| 30 m | 1.10 | 219 |

0.5 px 落在悬崖左侧两倍余量处，稳妥。而 60 Hz 下修正常用次数：

| 档位 | m | 修正占比（仿真） |
|---|---|---|
| 3 m | 1 | 98.2 % （持续接触时每帧修，见下） |
| 10 m | 2 | 49.1 % |
| 30 m | 6 | 16.4 % |

**3 m 档在持续接触下无法省成本**：`allow = 1.79 mm < d = 2.72 mm`，`m` 只能是 1。
这是近距离高精度应付的代价，曲线如实显示。若必须省，只能降可见阈值或接受
接触帧的极小残留——规格里不默认这么做。

## 5. 必须声明的界限

配额约束的是**渲染深度**，不是积分器算出的原始深度：

- 落地帧原始深度只取决于帧相位。10.84 m/s 冲击时每帧走 180.7 mm，实际落点
  在 `[0, 180.7] mm` 内某一处。修正在呈现前执行，所以渲染值仍 `≤ allow`。
- 原始深度始终 `< 直径 1000 mm`，球不会到地板的另一侧——“没穿过”成立，但
  “原始深度小于 1 mm”这种说法不成立。
- 测试用负对照（`*_detects_overcap_sink`，配额放到 3×A_vis 必须能看见）证明
  “可见次数为零”不是测不出来的空断言。

## 6. 跑法

```
make test      # 规格自检，末尾打印 spec_quota_mm
make curves    # 生成两条曲线的 CSV
make clean
```

依赖只有 CC + libm。改 `src/penetration.c` 顶部的常量（分辨率、FOV、相机高度、
`K_CAP_PX`、石头半径）后重跑，表和检查会一起变。
